# Megabit Trajectories

Verified coding-agent trajectories generated by [Megabit](https://github.com/Sumama-Jameel/megabit) — execution-grounded process data for LLM pretraining.

Each episode reconstructs the real development process behind an open-source commit: an agent explores a codebase, reads the ticket, implements the fix, runs tests, and iterates through review rounds. Every tool call, terminal output, and reasoning step is captured verbatim.

## Episode Structure

```
episodes/<task_id>/
├── <task_id>.episode.jsonl      # Full trajectory (all events)
├── <task_id>.sample.jsonl       # Training-ready sample
├── briefing.md                   # Agent instructions
├── ticket.md                     # Task description
├── hints.md                      # Codebase hints
├── config.snapshot.json          # Runtime config
├── setup_state.json              # Environment setup state
├── feedback/
│   ├── round_1.md                # Reviewer feedback (round 1)
│   └── round_2.md                # Reviewer feedback (round 2)
└── logs/
    ├── coder.ndjson              # Coder agent events
    ├── reviewer.ndjson           # Reviewer agent events
    └── retry_journal.jsonl       # Provider fallback log
```

## Episode Format

### `.episode.jsonl`

Newline-delimited JSON. Each line is one event:

```jsonl
{"type": "episode_header", "generator": "megabit", "task_id": "...", "repo_name": "...", ...}
{"type": "tool_call", "name": "read", "args": "{\"file_path\": \"...\"}", ...}
{"type": "tool_result", "name": "read", "output": "...", ...}
{"type": "agent_invocation", "session_id": "...", "final_response": "...", ...}
```

Event types: `episode_header`, `tool_call`, `tool_result`, `agent_invocation`

### `.sample.jsonl`

Single JSON object per file. Contains the same trajectory in a training-ready format with provenance metadata.

## Generation

Trajectories are generated using the Megabit pipeline:

1. **Task extraction**: Mine commit diffs from MIT/Apache-licensed repos (SWE-bench format)
2. **Sandbox setup**: Clone repo at base commit, install dependencies
3. **Agent execution**: Coding agent explores, implements fix, runs tests
4. **Review cycle**: Reviewer agent evaluates changes, requests revisions
5. **Verification**: Confirm tests pass and diff matches target

## Use Cases

- **SFT training**: Fine-tune coding models on verified trajectories
- **RLHF data**: Use as demonstration data for reward modeling
- **Evaluation**: Benchmark coding agents against known solutions
- **Research**: Study agent behavior, tool usage, and error recovery
